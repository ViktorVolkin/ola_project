# Published Sanity → local JSON (one way)

```sh
npm run content:sync -- --locale ru --dry-run
# Read-only reconciliation of the owner's exact frozen 120-change approval:
npm run content:sync -- --locale ru --dry-run \
  --approved-report docs/qa/quality/content-sync-001/dry-run-report.ru.json \
  --approved-sha256 8cf29a9d2fb943be5026f1f69a7fc4a0a93e0b2f344571b99df0772f51f7fa39
# ONLY in a later separately authorized application task, after Supervisor PASS:
npm run content:sync -- --locale ru --write \
  --approved-report docs/qa/quality/content-sync-001/dry-run-report.ru.json \
  --approved-sha256 8cf29a9d2fb943be5026f1f69a7fc4a0a93e0b2f344571b99df0772f51f7fa39
```

Default is **dry-run**. Optional `--page home|about|weddings|balloons|bouquets|contact` narrows both the published query and writable dictionary set. `--locale` accepts `ru|en|sr`; an explicit locale only authorizes that locale when the operator is otherwise authorized. Conflicting/unknown/duplicate arguments exit 2 before any network request. No environment variable bypass, preview client, tokens, drafts, mutations, parser fallback values, new dependencies or automatic write-after-preview.

Plain dry-run produces `reports/content-sync/<locale>.json` and `.txt`; pinned approval checks use `<locale>.approval-check.json/.txt`, and write attempts use `<locale>.application.json/.txt`, leaving the approval input untouched. JSON contains every exact old/new proposal (including segment paths), all skip reasons, blockers, per-page totals, original dictionary hashes, shared allowlist hash, and published document IDs/revisions/snapshot hashes. TXT includes the entire proposed old/new list with JSON-escaped newlines/quotes so nothing is hidden by terminal wrapping. Guarded outputs also record approval path/hash, match status and exact differing field paths. A blocker exits 1; a successful plan/write exits 0. A failed or recovery-required transaction is not a successful application; `applied: true` is set only after successful commit, readback and cleanup. Inspect blockers/recovery state rather than assuming `applied: false` means a recovery failure left no changed bytes.

## Required approval binding (added application-readiness condition)

The historical plain `--dry-run` then `--write` sequence was **not** binding: each invocation re-fetches. It is no longer sufficient. Plain `--write` now refuses publication without both `--approved-report` and `--approved-sha256`. This is a deliberate backward-incompatible safety tightening, not a claim that the initial generic CLI specification required these flags. The digest must be the owner's already-approved lowercase SHA256, supplied independently of the current file. Never calculate a new digest from changed copy and treat that as renewed approval.

`execute` loads a confined regular single-link approval file, verifies its pinned byte hash **before parsing or fetching**, strict-parses it (duplicate/prototype keys rejected), and requires a successful unapplied dry-run. It obtains **one** prospective published snapshot for the exact selected cohort, compares version/locale/complete selection/perspective, every old/new/segment/local/source path, skips/page totals, the complete recorded dictionary-hash set, mapping hash and every published document ID/type/revision/snapshot hash. Missing revisions or any drift block publication and report differing paths; equal counts alone never renew approval. It then commits **that same captured plan**, not a re-fetch. Approval bytes/inode/path confinement join the existing precommit, after-staging and per-rename guards; replacements/symlinks/hardlinks/path escapes are refused. The existing exported low-level `planSync`/`commit` APIs remain transaction primitives, **not approval-authorized application entry points**; callers applying approved content must use guarded `execute`.

The frozen report predates this correction and does not hash every code file. The binding is exact local/mapping/remote/proposal semantics, not a blanket veto on unrelated source edits. The current schema/config and code-owned ordering are collected/guarded in planning; corrected parser/loader/guard/transaction source must match the final rereview packet before later application. Verify that final-source hash receipt in the authorized application task, and use an exclusive/quiescent workspace. Approval pinning is not a cryptographic owner identity/signature or protection against a malicious operator supplying a different report **and** digest. Arbitrary noncooperating filesystem races retain the limitations below. A successful read-only reconciliation is a point-in-time observation, not permission to run a fresh unguarded write or a promise the CMS has remained unchanged.

## Selection rules

- Reuses `content-diff`'s **published GET loader**, schema traversal, code-owned ID order, comparison and the same single explicit mapping. No duplicate mapping or diff report rewriting. The only shared-core change exports the already-loaded mapping source to reject stale mapping modules.
- Valid nonempty mapped raw strings replace **existing string tokens only**. Exact Unicode, whitespace, quotes and line breaks survive. No object/array creation, reordering, array shifting, images, other locales, components or fallback changes.
- Absent/null/whitespace CMS fields retain local values. Non-string or parser-invalid text (over 10,000 UTF-16 code units or angle brackets) is skipped with a reason. The predicate mirrors the existing production parsers without importing their fallback output.
- Unmapped/local-only text is never written. A nonempty unmapped CMS string is an explicit transaction blocker, including schema fields with no local destination and unknown raw CMS text. Empty schema slots alone are not blockers.
- Named ICU placeholders must retain exact names and multiplicities. Reordering is permitted; omission/addition/renaming is blocked. Single-apostrophe brace quoting (including unclosed quotes) is deliberately unsupported and blocked on either old or new text: `Hi '{name}'` is literal text, not the `{name}` substitution. Doubled apostrophes and ordinary prose apostrophes (`don't`, `l'amour`, `O'Brien`) remain supported. Complex/malformed ICU is still blocked for manual review rather than approximated or rewritten. Angle-bracket/rich text is not imported.
- JSON is strict-parsed then token-edited using the existing TypeScript AST dependency. Duplicate keys, protected prototype keys and colliding dotted paths are rejected. Segment arrays disambiguate nested arrays and literal-dot property names. UTF-8 is decoded strictly; BOM, indentation, key order, CRLF/trailing newline and every byte outside edited string tokens are preserved.

## Transaction safety and limits

The entire selected local/schema/mapping/published snapshot is collected and validated before writing. Network errors, missing/duplicate/wrong-type/draft/unsolicited singleton docs, ambiguous mapping/schema, stale inputs or placeholder blockers cannot initiate a dictionary write. Source dictionaries, common dictionary, code-owned ordering, Studio config and mapping are checked again before committing (real CLI root). Paths are confined to existing regular single-link page/locale files under `src/i18n/messages`; symlink ancestors/targets and report escapes are refused.

`reports/content-sync/.transaction` is an exclusive cooperating-writer lock and a recovery directory. Each transaction saves exact original/proposed bytes and a manifest, then stages all proposed files in their destination directories. Source hashes/inodes are checked before the first rename and again before each rename. Staged content identity is checked, permissions are preserved, and exact targets are read back. Runtime failures trigger reverse rollback of owned changes. A changed destination is **not** overwritten during rollback. Unknown/replaced staging files or journal entries are not cleaned up. Rollback/cleanup conflicts retain the transaction and block subsequent sync (including dry-run).

**Not crash-atomic:** multiple renames are not one atomic filesystem transaction. SIGKILL, power loss, disk failure or rollback failure can leave partial publication. Backups/manifest support manual recovery, but this is not a fully fsynced durable journal with automatic crash recovery. Individual rename visibility can expose a mixed version to simultaneous readers. Also, ordinary portable Node filesystem operations do not provide compare-and-swap rename against arbitrary non-cooperating writers: a narrow check-to-rename/ancestor replacement race remains. Run future approved writes with editors/formatters/watchers stopped and an exclusive/quiescent workspace; do not claim protection against malicious concurrent filesystem mutation. Ownership/ACL/extended attributes are not preserved beyond file mode. These limitations do not waive owner approval or independent review.

### Recovery

Do not blindly delete `.transaction` or retry. Stop writers; inspect `manifest.json`, each `<n>.original` / `<n>.proposed`, and actual target hashes. Preserve any owner edits. Choose restoration or completion manually under separate authorization, verify exact bytes for every target, then remove only positively identified transaction/staging files once reconciled. Recovery is intentionally not automated or exposed as an override flag.
