# Frontend integration and QA

## Risk-proportionate page-completion gate

These full-page checks apply to new complete pages and substantial shared UI/integration, not mechanically to every isolated low-risk edit. One executor owns diagnosis/repro/root cause as applicable, fixes, integrated checks, evidence and its own final record. Lead commissions/controls evidence only: never project writes, artifact-producing checks or code review. Low isolated work without an explicit gate may use confirmed executor checks. Medium/high/critical or explicit gates require actual @supervisor on runtime-confirmed gpt-6.1-sol, never a named child. OLA-ORCH-002 explicitly requires actual review; OLA-WF-001 remains BLOCKED until its own gate resolves. Supervisor may write only its own review receipt/fields after explicit target permission, never fixes or another executor's accounting. A completion banner is not acceptance.

1. **Full affected-code review:** inspect every new/changed page, widget, content/message module, route and shared dependency. Trace real imports/usages; verify dependency direction, types, server/client boundaries, semantic HTML, design fidelity, supplied assets, i18n ownership, dead code and unnecessary duplication. Compare questionable APIs with the installed framework/library documentation before calling them obsolete.
2. **Production quality gates:** run the project's relevant lint, typecheck, unit tests, production build and integrated browser suite after final edits. Include affected existing pages when shared chrome or primitives change. Do not call a partial/timeout run PASS.
3. **Actual responsive inspection:** open the rendered page in a real browser at Figma reference widths 360/768/1440, narrow and intermediate widths, wider desktop and ±1px around retained composition transitions. Inspect actual section-sized screenshots, wrapping, image composition, vertical rhythm, overlap, horizontal overflow, touch targets and fixed elements. A successful text assertion does not establish visual correctness.
4. **Interactive behavior from this page:** exercise every implemented control. In particular, open/close the compact header modal, use Close/backdrop/Escape/navigation links, cycle Tab/Shift+Tab, verify focus containment/restoration and background scroll blocking, operate the nested locale selector, switch EN/RU/SR, and resize while the menu is open. Check other real page interactions, including forms/selectors/galleries where present; verify deliberately disabled actions stay explained and disabled rather than inventing destinations.
5. **Language and route checks:** cover EN/RU/SR, longer labels, Cyrillic/Serbian Latin rendering, active navigation, locale-preserving links and intended route/404 behavior. Distinguish intentionally unimplemented routes from regressions.
6. **Runtime checks:** inspect browser console/page errors, hydration failures, failed required asset requests, inaccessible controls and broken applicable links. Test keyboard operation and visible focus, not just mouse clicks.
7. **Fix or escalate:** FAIL returns exact findings to the original executor for scoped correction/rechecks; do not add a third fixer. If that child ended, provide a bounded continuation from its checkpoint, not a claimed technical resume. Uncertain product/design/architectural decisions require the appropriate owner. Real required-access BLOCKED stops affected work until cause resolution, without blind retries, setup repair or interface bypass.
8. **Evidence and closeout:** preserve initial failures, rebuild and rerun affected checks after corrections, tie screenshots/results to the actual build/source, and report remaining limitations explicitly. Owner/Lead Designer design acceptance remains separate from technical QA. Do not claim a complete page while known substantive defects or unperformed required gates remain.

## CSS pipeline regression checks

1. Inspect installed Next configuration/docs and reproduce both global-token and component-layout behavior in the browser before changing loaders.
2. With a Tailwind Turbopack loader that rewrites input via `as: "*.css"`, scope the rule to the actual global stylesheet basename (for example `globals.css`) rather than all CSS. Let native Next process ordinary `*.module.css`; rewriting modules as global CSS loses their exported class mappings.
3. Validate both halves together: assert a computed theme background and a component's expected computed layout, then run the production build/browser suite. Correct global colors alone do not prove CSS Modules work, and generated module classes alone do not prove Tailwind processed `@theme`.

## CSS Module extraction and ownership

1. Inventory the original base rules, media rules and JSX class usages before splitting a stylesheet. Move whole section-owned rule groups, not substring-selected class prefixes: `.hero` and `.heroCopy` are different selectors, and dropping the latter can destroy vertical alignment while all content tests still pass.
2. Trace descendant selectors across module boundaries. A section module's `.storyText .heading` cannot target a heading that carries only a separate typography module's hashed class. Export a local alias with `composes: heading from "./AboutTypography.module.css"` and apply that local export in JSX, or apply both explicit local and shared classes. Keep the shared module limited to genuinely common typography.
3. Preserve image overrides when moving `cover` into a common module. A local `.photo .cover` stops matching an image that carries only the common module's class; use the explicit class strategy above or a narrowly scoped `.photo img` when every image in that wrapper shares the intended crop.
4. Audit all `styles.*` usages against actual exports after extraction, including rules that exist only in media queries. CSS Module index typings can allow missing exports through TypeScript, so typechecking is not a selector-integrity gate. Add a focused static regression test that resolves both relative and `@/` stylesheet imports before checking explicit class usages; retain browser assertions because selector presence does not prove a descendant rule matches.
5. Keep shared presentation defaults lower-specificity than widget overrides, for example `:where(.editorial)` and `:where(.handwritten)`, so CSS import order cannot silently replace section gaps, caption sizes or colors. Reassert intended composition-specific spacing in the owning widget rather than depending on a common module loading last.
6. Rebuild, then compare actual heading/body positions, widths, image crops and section heights with pre-refactor evidence at approved control widths. Also sweep intermediate widths and the neighbors of each newly chosen breakpoint. Document actual remaining breakpoints with the composition constraint each resolves, not merely a tablet/desktop label. Replace size-only breakpoint adjustments with interpolation when composition is unchanged. Match repeated text by a stable section/element identity or exclude ambiguous duplicates; keep viewport width and geometry deltas in separate fields so a width delta cannot overwrite the viewport identifier.

## Server/client locale integration

1. Keep page composition and common chrome server-rendered; pass translated labels into the actual interactive islands.
2. When next-intl client navigation hooks require context, supply an explicit locale through `NextIntlClientProvider` with `messages={null}` if islands already receive labels. A context provider around server-rendered children does not require turning those children into Client Components.
3. Add page UI namespaces to both the server request loader and AppConfig message augmentation; verify actual locale rendering, not just the shape of JSON files.
4. Make SSR disclosure triggers unavailable until hydration attaches handlers if early clicks can otherwise be lost. A `useSyncExternalStore` readiness snapshot (server false/client true with stable no-op subscription) supports this without a state-setting effect. Test activation, Escape/focus restoration, outside click, nested disclosures and locale route/query/hash preservation.

## Responsive browser checks

1. Run semantic and interaction checks against a production build; include supported locales, approved widths and narrower/intermediate widths. Stabilize changed behavior with focused tests, then run the integrated suite after the final source edits. Run large screenshot/image-decoding sweeps separately from CPU-heavy Playwright matrices rather than launching several browser workloads concurrently; contention can turn otherwise passing checks into timeouts. On timeout retain partial output; inspect existing task evidence and stop affected work BLOCKED if a required infrastructure prerequisite is unavailable. Re-run an interrupted scope only after its cause is resolved within authorization, never count partial output as a pass.
2. Batch DOM measurements with `locator.evaluateAll` per viewport rather than issuing separate browser calls for every attribute of every control; excessive round trips make geometry tests time out without revealing an application defect.
3. Exclude only explicitly intentional scroll-rail overflow from page-bound checks. Preserve touch-target and document-overflow assertions elsewhere.
4. If an aspect-ratio card overflows below the reference width, inspect transferred minimum sizes: a fixed `min-height` can force a wider intrinsic box. Allow the ratio to shrink and use `min-width: 0` where appropriate instead of hiding document overflow.
5. Measure the photo container when checking viewport dimensions. `getBoundingClientRect()` on a transformed image includes its deliberate crop enlargement, not the clipped visible photo size.
6. Exercise native horizontal scroll with ArrowRight/ArrowLeft and verify actual scroll movement or link reachability. Do not require End to mean horizontal-end unless the component explicitly implements that behavior; native End can scroll the document vertically.
7. Decode images, return to the capture position and allow a repaint before saving evidence. Do not await every below-fold lazy image indefinitely: activate loading in the QA page or scroll it into view, bound decode waits, and record incomplete/natural-size failures. A terminal timeout may leave the capture runner and browser descendants alive; verify and stop only those task-owned processes before rerunning. Record navigation-cancelled Next RSC prefetches separately from failed required images or runtime errors. Inspect full-page captures in section-sized crops; a tall image downscaled to a thumbnail cannot establish typography or cropping fidelity. Check suspicious blank imagery with a fresh viewport capture and image decode/natural-size evidence before changing CSS.
8. Rebuild before rerunning production browser checks after source edits; an existing `next start` serves the previous build. Tie final captures to the actual build ID and a reproducible source hash, and retain initial failing captures separately.
9. Target semantic headings/regions and inspect their actual containers for geometry or contrast assertions. Never use an unscoped `.ctaCopy`-style selector for a CSS Module class; a zero-element match is a test-selector defect, not evidence that the component is missing.
10. Treat overflow, position and contrast regressions as separate assertions from content presence. A page can pass text/order tests while its main photo is inset incorrectly or pale CTA copy is unreadable; inspect native fills rather than assuming every dark OLA surface is wine.

## Modal navigation test selectors and interaction gates

1. Inspect the rendered dialog DOM before writing backdrop tests. Do not assume Radix emits a `[data-radix-dialog-overlay]` attribute; add an explicit stable data attribute to the owned Overlay when a test needs to address it. Click a point actually outside the Content rectangle, not an arbitrary point covered by the panel.
2. Locate background elements with hidden-aware selectors while the modal is open. `getByRole("banner")` normally excludes a header hidden by the modal's `aria-hidden`; use `getByRole("banner", {includeHidden: true})` or the known native header element for background geometry and hidden-state assertions. Even `includeHidden: true` does not guarantee a hidden trigger keeps its accessible name: assert the translated name before opening, then locate the background trigger through a stable native/data selector to check `aria-expanded`, `aria-controls` and focus restoration. A failed named-role lookup can demonstrate correct isolation rather than a missing control.
3. Cycle Tab and Shift+Tab far enough to cross both focus boundaries, then check Escape, Close, backdrop and navigation-link dismissal plus trigger restoration. Assert real wheel-scroll blocking/restoration and unchanged background-header geometry in addition to the body's computed overflow.
4. For disclosure keyboard regressions, distinguish focus moving within the trigger/link group from focus leaving it. Have the worker test Tab/Shift+Tab boundary exits and assert that dismissal does not steal focus back from the destination; retain Escape's separate trigger-restoration checks. Verify the intended behavior in the existing control contract rather than inferring a defect from source alone.
5. Test the nested language disclosure separately: first Escape must close the child while retaining the dialog and scroll lock; a subsequent Escape must close the dialog. Radix handles Escape in document capture phase, before a child's React bubbling handler: use Dialog.Content's `onEscapeKeyDown` to prevent modal dismissal when the event target belongs to an open language disclosure, then let the child's handler close it and restore its trigger. Expose that child state explicitly instead of inspecting hashed CSS classes. Exercise Escape from both the trigger and a focused language link in EN/RU/SR; also verify locale-specific header context and resizing an open compact menu into visible desktop navigation.

## Figma asset verification across tool backends

1. Establish file identity before reading sections. A canonical URL recovered from a project receipt supplies a candidate file key, not proof that it matches the active plugin session; verify the expected file/root names and node IDs through a permitted read interface. With Figwright, bind each agent explicitly using `use_file`; the parent's binding does not establish a child's binding. Do not infer node deletion from an unbound session or silently override an explicitly required interface.
2. Ground the whole page, then inspect sections. When a full-frame context spills to an artifact, recover that artifact with permitted file tools instead of requesting the same root again. Use compact metadata to identify section IDs, then batch independent full-context section reads with screenshots. Metadata or a preview containing only asset constants is insufficient for implementation. Pass an existing inspection session ID on follow-up tools that accept it.
3. Distinguish frontend filesystem paths from the Figma server's artifact/export paths. In the Docker workflow frontend tools use `/workspace`; an exporter may instead require the provided project host root. Use a bounded project evidence directory, then verify access through the frontend mount. A returned host artifact path is not permission to inspect unrelated host directories, change mounts or bypass file-tool policy.
4. Inspect actual IMAGE-bearing descendants, not only component roots. For programmatic inspection, resolve the known page/frame by ID, use an indexed descendant-type lookup, and return only image node IDs/names, original hashes, source dimensions, fill mode/transforms and relevant geometry. Bound serialized output size; avoid broad document dumps or mutating Figma to make a read work.
5. Match original image hashes and dimensions against supplied runtime bytes. Do not compare a re-rendered/resized PNG with original JPEG bytes and call a mismatch a missing asset. Preserve native node IDs, local public paths, source identity and explicit unmatched cases in the asset map; filename resemblance is not verification. Record which responsive fills were actually checked, because desktop identity evidence alone does not cover tablet/mobile. If Figwright context/get_node serializes IMAGE scaleMode without imageHash, do not invent the missing hash or repeatedly query the same stripped view: use save_image_fills on the actual IMAGE-bearing leaf to obtain original bytes/hash. Export only into the known project evidence directory, distinguish host/tool paths from the frontend mount, and verify readback SHA1 against the returned native hash and supplied asset; also check export ownership before relying on cleanup. These exports are verification evidence, never substitute screenshots or duplicate runtime sources.
6. Inspect composition independently of source identity. Starting from each photo rectangle, follow ancestors to its actual clipping viewport and record both rectangles, offsets and visibility. A FILL paint with identity `imageTransform` can still have a deliberately enlarged/off-centre image rectangle outside a clipped parent. Reusing the correct scene in a detail thumbnail therefore does not justify a separate asset or a default centered cover crop.
7. Preserve responsive crop exceptions explicitly. Compute image-to-viewport ratios and relative offsets with executable arithmetic; document them as reference geometry before choosing CSS. Check the inner image's own FILL behavior as well as the outer clip, and validate the result in the browser at reference and intermediate widths. Use fluid interpolation where composition is continuous; retain art-direction transitions only where the references require them.
8. Respect ancestor visibility when interpreting extracted text. A hidden mobile Navigation subtree can contain a page label without that label being visible in the closed header.

## Font migration and actual glyph verification

- Investigate locale-specific CSS overrides before blaming glyph coverage. Great Vibes supports Cyrillic in the supplied/current Google files; do not substitute Cormorant italic for Russian based on an unverified assumption.
- Preserve CSS variables when changing font loaders. Check installed Next Google font signatures for supported subsets/styles/variable weights, then exercise a real build with network access.
- Use Chromium CDP `CSS.getPlatformFontsForNode` on actual text nodes to establish the font that drew the glyphs. Computed font-family and `document.fonts.check` alone cannot rule out fallback. Variable fonts may report internal default-instance family names such as Cormorant Garamond Light or Manrope ExtraLight even when CSS selects another weight; distinguish family metadata from computed weight.
- Compare pre/post heading dimensions and section screenshots across locales. Different Google web-font metrics can change normal wrapping without creating a defect; inspect changed sections instead of forcing old heights or reducing type size.

## Local server takeover

1. Stop the tracked task-owned dev server through process management.
2. Verify listener state, even if the process tracker says the wrapper already exited. If necessary, identify the surviving Next child by command, project cwd and process ancestry before terminating it; never kill every Node process or an unidentified listener.
3. If a listener utility is unavailable, use a Python socket `connect_ex(("127.0.0.1", port))` probe to check whether the port still accepts connections. This is a listener check, not permission to stop an unknown process.
4. Confirm the port is free, provide the repository's existing start command and local URL, and leave development paused until the user requests continuation.
