# OLA frontend workflow

## When to Use

Use for OLA foundation setup, localization, routing, approved-design implementation and frontend verification.

## Lead ownership and mandatory gate

Lead is read/plan/route/evidence-control only. Never create, patch, integrate or repair project files (including documentation, configuration, tests and ledgers), run artifact-producing checks, bypass through shell/scripts, or perform code review. One executor owns a coherent task's diagnosis/reproduction, minimal change, necessary checks, evidence and task accounting. Split only independent scope, materially different specialty/risk, or a true blocker. Avoid separate diagnosis/accounting/formatting/relay agents and automatic stage-review/fixer chains. Preserve user work; no automatic Git changes.

Set explicit risk and rationale. Luna (`gpt-6-luna`) for simple local/docs/routine work; Terra (`gpt-6.1-terra`) for React/Next integration/moderate debugging; Sol (`gpt-6.1-sol`) for architecture/security/auth/payment/data integrity. Truly local isolated low-risk work needs verified executor checks; supervisor not_required. Medium shared behavior/integration/substantial UI, high/critical, or explicit independent-review requirement goes only to actual @supervisor gpt-6.1-sol with runtime evidence. Never downgrade risk to avoid review. The cross-cutting OLA-ORCH-002 package explicitly requires actual Sol Supervisor review; OLA-WF-001 stays BLOCKED until its own explicit gate is resolved. Preserve the original verdict; FAIL returns to same executor/context where feasible, a terminated delegate may not be resumable, and required unavailable access means BLOCKED.

No recurring tool/connection health or model-config preflight campaigns. Read practical task materials/dependencies as normal work. Real required-access BLOCKED stops affected work until its cause is resolved; no blind retries, setup repair, reconnect or bypass. Infrastructure belongs to the owner/authorized engineer, not a mandatory setup stage. Do not alter model/provider/auth/config/tool permissions. Actual runtime evidence establishes identity; unknown stays unknown.

## Procedure

Implementation, integration, checks, captures and document updates below belong to the assigned executor within its explicit writable scope. Lead only analyzes, routes, coordinates and controls evidence; it never executes those writes/checks or code review. Persistent edits do not replace already injected live instructions.

- Load `model-quality-accounting` for nontrivial execution. The executor owns its final project-local record, with actual evidence, corrections and unknowns. Historical direct/delegated/hybrid fields describe what happened, not permission for Lead writes. No separate bookkeeping agent or Supervisor takeover of implementation accounting.

- Read the current README and task scope; historical readiness reviews are not current requirements. Re-check Git branch and working/staged changes. Keep OLA work on `development` unless explicitly instructed otherwise. Preserve pre-existing edits/deletions; do not stage, commit or push without authorization.
- Respect the user's current reporting preference. Default OLA delegation update: `Запускаю: [роль] — [краткая задача]. Доступ: [read-only / может изменять файлы].` During quiet autonomous work omit routine milestones and do not answer pure delivery/completion notifications with repeated status messages; a message-delivery process exiting successfully does not prove the recipient completed its task. Report genuine blockers once, with their effect on delivery, and parent-verify delegated results. During authorized autonomous continuation, make ordinary scoped engineering decisions without asking for confirmation; defer unresolved product/design or approval-gated portions and advance independent work instead. Never interpret this preference as permission to invent requirements or bypass security/approval gates. Respect explicit owner route selections and the tier guidance above; never use the Luna900k variant. Verify actual runtime routing rather than assuming a model name in task text changes execution.
- Treat lighter subagents as bounded implementers, not technical owners. Give exact file ownership, inspected API/component shapes, required assets/content, explicit non-goals and executable acceptance checks. Prefer one clear section or behavior per task over whole-page autonomy; provide the needed source excerpts instead of vague discovery requests. Keep architecture, Figma interpretation and coordination with Lead; delegate integration and all execution. Require executor check artifacts and use actual @supervisor only when risk or an explicit gate requires independent review. Do not accept a child's success claim or cheap-model preliminary review as the final gate. A compiling translation dictionary can still contain mixed-language fragments, changed meanings and wrong grammar; assign RU/SR semantic and visible-label checks to an appropriate worker and include findings in the Supervisor packet even when draft status is explicit. Docker frontend tools use `/workspace`, not the host project cwd. A host-only path returning errno 2 is not proof of host absence or policy denial. If required review access is missing, mark BLOCKED and provide authorized evidence through the assigned executor; do not silently substitute a tool-less review or repair the environment. Require worker reproduction before treating an accessibility suggestion as a defect. Visually hidden text can still provide an accessible name; require actual role/name evidence and a meaningful RED regression before adding ARIA. Likewise, passing widget-local CSS Module classes through a shared component's className API is not itself a layering defect. Preserve rejected diagnoses as reviewer-quality evidence, not implementation rework.
- Assign one executor per coherent full task cycle, including implementation, correction, checks, useful evidence and its own logical final accounting. Split only independent scope, materially different specialty/risk or a genuine blocker; no compulsory fresh stage agent, reviewer chain or third fixer. Risk/explicit gates require only actual @supervisor on runtime-confirmed Sol. Supervisor writes only its own review receipt/fields after explicit target permission; never finishes another executor's implementation accounting. Checkpoints serve long, expensive or interrupted work. Resolve real design ambiguity with Lead Designer only when necessary.
- Do not inspect Figma or implement design pages during foundation-only work. Once authorized, inspect the complete requested page and relevant responsive states, map Figma ↔ supplied assets ↔ routes, identify reusable patterns, and record the implementation plan before writing UI.
- Resolve conflicting design sources with the designer rather than treating a newer-looking board name as authority. Use the latest explicitly agreed interaction contract rather than reviving an older archived brief or copying another page's CTA behavior. Record explicit supersession decisions and distinguish full-card dimensions from photo viewports; accepted reference widths/heights are snapshots, not fixed CSS requirements for every viewport. When Figma represents one paragraph as separate line TEXT nodes, verify the semantic flow requirement before enforcing its apparent line count: preserve one natural paragraph and approved available width, and record any explicitly permitted height difference instead of inserting blank lines, forced breaks, narrow max-widths or fixed-height spacers for tool-only geometry.
- Verify photograph identity separately from composition at every reference state. An identical image hash or identity fill transform does not prove centered cropping: inspect the image rectangle's dimensions/offsets and its clipping ancestors, including nested instances. Preserve the supplied source and implement the measured crop instead of substituting imagery or assuming plain centered `object-fit: cover`. Follow the Figma asset recipe in `references/frontend-integration-qa.md`.
- Keep design clarification separate from implementation authorization. Treat supplied photos as mocks, label unapproved translations as drafts, and use explicit nullable-contact/disabled-action preview states instead of invented destinations. Preserve unresolved product decisions without silently settling them.
- Use already approved design materials/access as ordinary task work, not a health/reconnect campaign. Official Figma quota says nothing about Figwright; missing schemas describe the current surface, not global plugin state. If a required fresh inspection is genuinely unavailable, stop that affected scope BLOCKED without repair/retry/interface bypass. Independent integration may use captured current approved intake only when freshness is not a gate; preserve provenance and do not claim fresh visual acceptance. The executor saves relevant rendered evidence with locale, viewport and build identity in its authorized project folder.
- Assign one executor for the full cycle and final concise evidence packet. Verify task materials and dependencies as part of ordinary work; no recurring health-check campaign or setup repair. If required access is missing, stop BLOCKED and report exact boundary. Do not alter tool/model/provider/auth/config permissions.
- Preserve `app → components/pages → components/widgets → components/shared`. Compose pages from meaningful named section blocks (e.g. HomeHeroBlock/AboutHeroBlock), not monolithic page JSX. Finished sections belong in widgets even when used by only one page; pages contain the main wrapper and composition, not section internals. Keep section styles below pages too: widgets must not import page-owned CSS or page components. Pages resolve their content/translations and pass typed content and ready labels into presentation blocks; avoid translator-function prop drilling. Use CSS Modules for authored styling, without Tailwind utilities or inline styles; make necessary reset/tokens explicit. Keep each widget's responsive markup, image sizes and section-specific CSS beside that widget; only genuinely shared typography belongs in a small common module. Use one Container system with explicit default/wide variants when design maxima differ, preserving full-bleed/asymmetric sections. Treat 360/768/1440 as reference points, not three fixed sites; justify widget-specific composition breakpoints instead of imposing600/1200 globally. Verify intermediate widths320/375/390/430/600/768/900/1024/1200/1366/1440 and wider, plus boundary neighbors. Compact navigation must be a proper modal overlay using an established dialog primitive, with scroll lock, focus containment/restore, Escape/Close/link dismissal and nested language control tested. Preserve visual behavior during architectural refactors. Document reserved layers instead of generating fake components, empty barrels or `.gitkeep` files. Move root app completely when adopting src/app and update aliases together; root app otherwise takes precedence.
- Treat a CSS Module split as a behavior change until browser-verified: audit every JSX class export and descendant selector, preserve cross-module typography/crop overrides explicitly, and compare section geometry at reference widths. Passing TypeScript or content-presence tests does not prove the extracted selectors still match. Follow the module-refactor and modal-test recipes in `references/frontend-integration-qa.md`.
- Keep responsive size changes fluid outside composition queries. Verify computed font-size/line-height at all three reference widths and across ±1px of both retained and retired thresholds; a clamp can still jump when a media override pins part of its range. Parse traditional and range-syntax queries when generating boundary checks. Actually exercise intrinsic wrap alternatives before claiming a discrete grid is necessary; preserve explicit pairing/span/rail/overlay art direction when the measured alternative changes its intended composition. Do not interpret a passing current-layout suite as proof that every breakpoint is necessary. Compare flex geometry too: a zero flex-basis plus padding can shift intended track proportions, while fluid arithmetic may round by a browser subpixel. For intrinsically wrapping tracks that must fill a singleton line, keep equivalent grow ratios with factors at least1: a lone fractional flex-grow below1 intentionally leaves free space. Probe the actual wrapped width in the browser, preserve the multi-track ratio, and add a regression for the singleton state. Compare actual photo viewports and inner crop rectangles at the reference widths; document natural locale-driven card growth separately from genuine crop/layout defects. Check section rhythm too: enlarged control layout boxes can accumulate vertical drift even with perfect photo crops. If preserving a small native visual line with an expanded transparent hit region, verify actual point hit-testing outside the visual box, avoid other interactive targets/clipping, and do not call it WCAG certification from CSS dimensions alone. Allow equivalent CSSOM serialization in assertions (for example, the default180deg gradient direction may be omitted); retain semantic direction/color checks instead of weakening the test.
- Check installed Next.js/next-intl documentation before selecting APIs. Modern versions support next/root-params for server locale resolution/static rendering. Validate locale before dictionary lookup. Do not add proxy/middleware reflexively when explicit locale URLs plus root redirect suffice; unknown locales must remain real404.
- Separate UI messages from catalogue/page content. Translate at the semantic owner; shared primitives receive labels, client islands receive only needed messages. Do not make whole pages client-side for translation.
- Test HTTP statuses against production: notFound after streaming can become a soft404. Cover unsupported locale and nested unknown routes, fixed redirect status and slash normalization. Also verify the actual server HTML/no-JS DOM includes the expected document language, main, heading and recovery links: status404 plus a response-body text substring is insufficient because copy can exist only inside inline Flight scripts while the real body is an empty `__next_error__` shell. Preserve a genuine framework delivery failure as an open gate; do not weaken the no-JS test, silently return200, patch framework internals or introduce routing/proxy/experimental workarounds without the required scope/approval.
- Runtime assets must not depend on ignored design-input directories. Preserve supplied mock imagery/provenance and verify manifests; final selection/rights is a release gate, not a frontend blocker. Use the owner's chosen `next/font/google` strategy for Manrope, Cormorant Garamond and Great Vibes, preserving their CSS variables, required weights/styles and latin/latin-ext/cyrillic subsets. Manually pinned font bytes and offline font builds are not project requirements; builds may fetch Google assets, visitors must not. Verify actual Cyrillic/Serbian Latin glyph rendering rather than assuming coverage from a family name.
- For uncommitted work, verify clean installation using an export of nonignored working files without node_modules, generated output, environment files or ignored design packages. Call this a source export, not a committed clone.
- Apply TDD selectively to routing, business behavior, validation, utilities and regressions. Do not require it for straightforward styling, static composition or Figma-to-code work.
- Prefer configured project lint/typecheck/build over automatic single-file checks that may ignore tsconfig. For Vitest Next extensionless imports inside next-intl, consider server dependency inlining instead of changing production code.
- Treat native-binding cache permission/noexec errors as container issues: use a trusted executable cache via environment configuration, not insecure permissions or product workarounds.
- For a new complete page or substantial shared UI/integration change, the executor verifies the integrated page and affected dependencies, EN/RU/SR production behavior, relevant reference/intermediate widths and breakpoint neighbors. Such medium-or-higher work requires actual @supervisor final review; truly isolated low-risk edits use proportionate checks unless explicitly gated. Retest affected modal, language, focus/scroll, navigation and other real states; screenshots or content assertions alone are insufficient. Use `references/frontend-integration-qa.md`, preserve failures and repeat affected checks after correction. Do not claim completion with unresolved mandatory gates.
- Review suspicious, obsolete or unnecessarily complex implementations against installed framework/library docs and project patterns. Fix clear local engineering defects within scope; report uncertain design/business behavior or changes requiring new dependencies/architecture rather than silently redesigning or modernizing unrelated code.
- The same executor reruns affected integrated checks after fixes; actual runtime-confirmed Sol @supervisor reviews when risk or an explicit gate requires it. Lead only coordinates/evidence-controls. An interrupted/unavailable required review is incomplete, never PASS. Keep spec, code, browser and visual verification distinct; config files do not prove remote CI/deployment ran. If Playwright exceeds budget, preserve partial coverage and use authorized disjoint batches against the same unchanged build; compute unique case totals without overlap.
- Maintain `docs/qa/pages/README.md` as the page-status entry point and link it from the project README. For every page record route/locales, implemented sections and ownership, code-review scope, responsive transitions/coverage, actual interactive checks, test commands/results, screenshot/build/source provenance, defects/fixes, pending inputs and release limits. Link historical page reports and later responsive/cleanup passes with explicit precedence; do not sum overlapping test runs or relabel old evidence as fresh. Check existing reports before starting a redundant audit; unimplemented pages must stay NOT IMPLEMENTED/NOT TESTED. Update the registry and detailed page QA report at each page completion.
- Before handoff, update README's actual status, file tree, content/message ownership and client-boundary descriptions; foundation-era statements become false when pages and chrome are integrated. Record responsive image substitutions in the asset map as well as JSX.
- When the user asks to stop the server and inspect locally, suspend development, stop only task-owned server processes, and verify that the requested port is free. A tracker reporting an exited npm wrapper does not prove its Next child stopped; do not restart the server or resume from delayed worker messages during user takeover.
