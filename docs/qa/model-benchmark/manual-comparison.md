# Сравнение моделей при ручном переключении субагентов

Владелец вручную выбирает модель. Lead запускает две одинаковые задачи A/B через `delegate_task`, проверяет ответы самостоятельно и добавляет результаты сюда. Не смешивать эти времена с прежними прямыми API-прогонами.

## Gemini 3.5 Flash-Lite — подтверждённый baseline

- Фактическая модель по gateway completion: `gemini-3.5-flash-lite`.
- Run: `20261104T115956Z`, delegation: `deleg_7b4333fc`.
- По одному свежему субагенту на A/B; оба параллельно. По одному API-вызову на задачу, без повторов. Общая длительность batch: **7,85 с**.
- Время отдельных детей по gateway: **A 7,43 с; B 6,01 с**. Это не отдельный замер API latency/TTFT/throughput.
- `usage`, стоимость, фактические temperature/reasoning/max-output этого delegation-прогона в уведомлении не раскрыты. Размер контекста/цены модели не устанавливались.

| Проверка | A: поиск багов | B: функция выбора |
|---|---|---|
| Завершённый ответ | Да | Да |
| Строгий JSON без Markdown/пояснений | Да | Да |
| Семантика | Обе категории проблем распознаны: невключительные границы фильтра и изменение массива вызывающего кода | Функция корректна на проверенном наборе |
| Точность инструкций | Не указаны первые ошибочные строки: ответ 2/5, ожидается 3/4. Первый fix шире локальной замены | Ожидаемые ключи, сигнатура, три сценария и их порядок соблюдены |
| Независимое исполнение | Диагностический ответ, не исполняемый код | **320/320 независимых случаев + 3/3 собственных теста** |

В B проверены удаление при достигнутом/превышенном лимите, запрет добавления при нулевом/заполненном лимите, добавление при наличии места, порядок, неизменность замороженного входа и новый массив при каждом возврате. Код просмотрен parent перед исполнением; `splice` применяется к копии, исходный массив не меняется.

**Наблюдаемые характеристики:** в этом небольшом прогоне быстро отвечает, соблюдает JSON-формат, уверенно реализует простую чистую функцию; при ревью кода распознаёт проблемы, но недостаточно точно локализует их по требованию. Это не общий рейтинг модели и не гарантия на других задачах.

В предыдущем прямом API-прогоне A был ограждён Markdown, а B проходил те же функциональные проверки. В новом delegation-прогоне формат A улучшился, но строки 2/5 остались. Сравнение скорости между двумя способами запуска не используется как доказательство ускорения модели.

## Z.ai GLM 5.3 Flash — запуск заблокирован параметрами запроса

- Фактическая модель по gateway completion: `glm-5.3-flash`; delegation: `deleg_6d1accd9`.
- Те же задачи A/B и контекст, что у Gemini baseline; два свежих параллельных субагента, по одному API-вызову, без повторов.
- Обе задачи получили HTTP 400: `This model always engages in thinking and cannot be disabled; please use low, high, or max`.
- Длительность отклонённых вызовов: A **1,19 с**, B **1,20 с**; весь batch **2,31 с**. Это время ошибки, не скорость генерации решений.
- Финальных ответов нет. Качество кода, следование инструкциям и скорость решения **не оценены**; провал интеграции не считается плохим решением модели.
- Конкретное тело запроса этого запуска не инспектировалось. В предыдущем диагностированном запуске GLM причиной был `reasoning_effort=medium`, хотя thinking был включён. Не делать по формулировке HTTP 400 вывод, что thinking здесь действительно выключен.
- Настройки не менялись. Перед новым тестом нужен совместимый reasoning (`low`, `high` или `max`); `low` — минимальный ранее предложенный вариант. Автоматический повтор без исправления не выполняется.
- [Артефакт попытки](deleg_6d1accd9/benchmark.json).

## Kilo Auto Free — оба задания выполнены

- Подтверждённый маршрут по gateway: `kilo-auto/free`; delegation `deleg_23edd970`. Конкретная downstream-модель этим уведомлением не раскрыта. Нельзя автоматически переносить наблюдавшийся раньше `reflection/beam-free` на новый запуск.
- По одному свежему субагенту на A/B; параллельно, два API-вызова, без повторов. Batch **21,57 с**; A **20,53 с**, B **12,63 с**. Это длительности детей/оркестрации, не standalone API latency.
- Программно подтверждено совпадение task prompts и system context с Gemini baseline. Наследуемые reasoning/temperature/token limits/usage/cost в уведомлении не раскрыты, поэтому равенство этих настроек не заявляется.
- **A: PASS.** Строгий JSON, правильные ключи/ID/порядок/unchanged; первые ошибочные строки **3/4** указаны точно. Parent проверил смысл fixes: копирование items в ветке all-in-range устраняет мутацию вызывающего массива, включительные границы фильтра исправляют вторую независимую ошибку. Лишних findings нет.
- **B: PASS.** Строгий JSON; чистая функция с правильным приоритетом удаления, сохранением порядка и новым массивом при каждом возврате. Parent просмотрел код перед исполнением. **320/320 независимых случаев + 3/3 теста модели**, включая неизменность замороженного входа. Тест запрета добавления при zero limit использует уже непустой массив: это допустимо, поскольку контракт не гарантирует selected.length <= limit.
- **Наблюдаемые характеристики:** в этом прогоне Kilo точнее соблюдает требования к диагностике, чем Gemini (строки 3/4 против 2/5); обе модели одинаково проходят набор проверок функции B. Gemini быстрее по обеим измеренным длительностям детей. По одному ответу на задачу недостаточно для устойчивого рейтинга; Auto Free является маршрутизатором.
- [Ответы, задачи и метаданные](deleg_23edd970/benchmark.json); [независимые проверки](deleg_23edd970/parent-verification.json).
