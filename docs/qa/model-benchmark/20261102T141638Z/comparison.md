# Итог небольшого сравнительного теста моделей

## Метод

Две одинаковые синтетические задачи без кода проекта и без инструментов:

- **A:** найти два независимых бага в JavaScript-функции, точно указать первые ошибочные строки и вернуть только JSON.
- **B:** написать чистую функцию выбора элементов с лимитом и тремя заданными типами тестов, вернуть только JSON.

Одинаковые system/user prompts, temperature 0, лимит генерации 1200 токенов и deadline 90 секунд. Запуски последовательные, один ответ на сочетание модель/задача, без fallback и повторов. Это тест прямых API-ответов, не сравнение автономных агентов с доступом к репозиторию. Лимит включает reasoning у соответствующих моделей; одинаковый численный лимит не гарантирует одинаковый бюджет финального ответа.

### Проверка функции B

Parent лично просмотрел оба сгенерированных тела функций и выполнил их в рабочем контейнере через Node.js. Проверены все упорядоченные подмножества `['a','b','c']`, четыре ID `a/b/c/z` и лимиты 0–4: 320 сочетаний для каждой функции. Входные массивы заморожены; дополнительно проверены правильные значения/порядок, неизменность входа и новый объект массива при каждом возврате. Три предложенных моделью теста проверены отдельно, включая соответствие заданным сценариям и их порядку.

Команды воспроизведения:


## Выводы и ограничения

- На **одной успешно решённой общей задаче B** Kilo ответил примерно в 5,06 раза быстрее Gemini. Это единичное измерение полного времени запроса, не доказательство постоянного преимущества, не throughput и не time-to-first-token.
- Gemini дал содержательные финальные ответы на обе задачи, но строгая дисциплина формата/точной локализации в A не выдержана.
- Kilo выглядит полезным кандидатом для коротких coding-задач, однако в A исчерпал бюджет без финального ответа. В обоих вызовах реально возвращён backend `reflection/beam-free`; это наблюдение, а не постоянная гарантия роутера. Kilo сообщил cost=0 для обоих вызовов; стоимость остальных маршрутов не вычислялась.
- Для Gemma выбранный бюджет не дал решения A, а B закончилась серверной ошибкой. Этого недостаточно, чтобы судить о способности модели решать задачи в иных настройках.
- GLM не оценён по скорости генерации, качеству или следованию инструкциям: вызов заблокирован балансом/пакетом. Ключ при этом позволил получить каталог; доступность каталога не доказывает право на inference.
- Нет статистически обоснованного общего рейтинга четырёх моделей. Ошибки API и исчерпание бюджета не превращаются в оценку качества несуществующего решения.

## Сверка фактических вызовов и маршрутов

Всего **7 inference-попыток из разрешённого максимума 8**: 5 HTTP/API 200, из них только 3 с непустым финальным ответом; 2 HTTP-ошибки. Восьмой запрос не потрачен, поскольку GLM B остановлен после billing blocker. Каталогов получено 4: исходные три и один корректирующий Kilo GET. Повторов inference нет.

Первоначальный разбор Kilo ошибочно выбирал `name` вместо `id`. Ошибка исправлена по фактической записи `id=kilo-auto/free`, `name=Auto Free`; прежний сырой артефакт сохранён неизменным. Обычный GLM Flash соответствует живому `glm-5.3-flash`; FlashX и Legal не подставлялись. Gemma вызвана напрямую через Google, не через Kilo.

Ключи использованы в отдельном штатном контексте `default`, где пользователь их сохранил. Credentials не копировались в Lead и не выводились. По проверке исполнителя настройки default/lead, credentials, delegation и код сайта не менялись. Сгенерированный код исполнялся только parent в рабочем контейнере, не исполнителем на хосте.
